## Description

### プロジェクト概要
本プロジェクトは、整数の並びを2つのスタック（a / b）と限られた11種類の操作だけを使って昇順にソートし、その操作列を標準出力に出力するプログラムである。

使用できる操作は以下の11種類。

| 操作 | 内容 |
| --- | --- |
| `sa` | スタックaの先頭2要素を入れ替える |
| `sb` | スタックbの先頭2要素を入れ替える |
| `ss` | `sa`と`sb`を同時に行う |
| `pa` | スタックbの先頭要素をスタックaの先頭に移動する |
| `pb` | スタックaの先頭要素をスタックbの先頭に移動する |
| `ra` | スタックaの全要素を上に1つずらす（先頭が末尾に回る） |
| `rb` | スタックbの全要素を上に1つずらす（先頭が末尾に回る） |
| `rr` | `ra`と`rb`を同時に行う |
| `rra` | スタックaの全要素を下に1つずらす（末尾が先頭に回る） |
| `rrb` | スタックbの全要素を下に1つずらす（末尾が先頭に回る） |
| `rrr` | `rra`と`rrb`を同時に行う |

### 目的
- 連結リストによるスタックというデータ構造の理解
- 計算量（O(n²) / O(n√n) / O(n log n)）を意識したアルゴリズムの選択と実装
- 「操作回数を最小化する」という制約下でのアルゴリズムの比較・評価

### 処理の概要
1. **引数のパース** — `--`で始まるフラグ（ソートモード・bench指定）を先に読み取り、残りを整数として検証する。
2. **スタックの構築** — 検証済みの数値から連結リストのスタックaを作り、各要素に「小さい順の順位（index）」を割り振る。
3. **乱れ度（disorder）の計算** — 全ペアのうち順序が逆転しているペアの割合を算出する。既にソート済み（disorder = 0）なら何も出力せず正常終了する。
4. **アルゴリズムの選択と実行** — 指定モード、またはAdaptiveモードならdisorderに応じてソートを実行し、操作列を標準出力へ出力する。
5. **bench出力（任意）** — `--bench`指定時は、disorder・選択された戦略・操作回数の内訳を標準エラー出力へ出力する。

### エラーハンドリング
以下の場合は`Error\n`を標準エラー出力に出力し、終了ステータス1で終了する。

- 引数に数値以外（`abc`、`1a`、空文字など）が含まれる場合
- INT_MAX / INT_MIN の範囲を超える数値がある場合
- 重複する数値がある場合
- 存在しないフラグ（`--hoge`など）が指定された場合

また、以下の場合はエラーではなく、何も出力せずに正常終了する。

- 引数がない場合
- 入力が既にソート済みの場合

### ソート戦略（Simple / Medium / Complex / Adaptive）
フラグでソートアルゴリズムを選択できる。指定がない場合はAdaptiveモードで動作する。

| モード | アルゴリズム | 計算量 |
| --- | --- | --- |
| `--simple` | 選択ソート | O(n²) |
| `--medium` | チャンク分割ソート | O(n√n) |
| `--complex` | 基数ソート（2進LSD） | O(n log n) |
| `--adaptive`（デフォルト） | disorderに応じて上記から自動選択 | 入力に依存 |

- **Simple（選択ソート）**
  スタックaの最小値を探し、回転数が少なくなる方向（ra / rra）で先頭まで回してbへ押し出す。これを繰り返すとbには上が最大となる降順で積まれるため、最後に全てaへ戻すと昇順になる。
- **Medium（チャンク分割ソート）**
  まず値を0〜n-1の順位に圧縮（compress）し、√n個ずつの「チャンク」に区切る。小さいチャンクから順に該当する要素をbへ押し出し（チャンク内の小さい半分はrbで下へ回して大まかに整える）、その後bの最大値から順にaへ戻す。チャンク分割によって戻す際の回転回数を抑えている。
- **Complex（基数ソート）**
  値そのものではなく事前に割り振った順位（index）を2進数とみなし、最下位ビットから順に「ビットが1ならraで回し、0ならpbで押し出す」を全ビット分繰り返す。比較を行わない安定ソートで、操作回数が入力の並びに左右されにくい。
- **Adaptive（自動選択）**
  disorder（逆転ペアの割合）が 0.20未満ならSimple、0.50未満ならMedium、それ以上ならComplexを選択する。ほぼ整列済みの入力には単純なアルゴリズムのほうが操作回数が少なく済むため、入力の乱れ具合で使い分ける。

なお、要素数が5以下の場合はどのモードでも専用の小規模ソート（2要素: sa、3要素: three_sort、4〜5要素: five_sort）に切り替わる。

### ソートアルゴリズムの正当性
- **three_sort** — 3要素の並び方は6通りしかなく、全パターンを場合分けして最短の操作列で処理しているため、常に正しくソートされる。
- **five_sort** — 最小値を先にbへ退避して残り3要素をthree_sortで整列し、最後に戻すため、three_sortの正当性に帰着する。
- **Simple** — 各ステップで「残りの最小値」を必ずbへ移すため、bは常に昇順（上が最大）で積まれる。paで戻すと必ず昇順になる。
- **Medium** — 最終段階の「bの最大値から順にaへ戻す」処理が選択ソートとして正しさを保証する。チャンク分割はあくまで操作回数を減らすための前処理であり、正当性には影響しない。
- **Complex** — 基数ソート（LSD）の性質による。同じビット値の要素の相対順序を保ったまま（安定に）下位ビットから処理するため、最上位ビットまで処理し終えた時点で全体が昇順になることが保証される。
- 加えて、同梱のテストスクリプト（`test.sh`）およびcheckerプログラム（`checker_linux`）で、出力された操作列を実際に適用した結果がソート済みになることを確認している。

## Instructions

### 実行方法
プログラムを実行する手順は以下の通り。

1. クローンしたいディレクトリまでカレントディレクトリを移動する。
2. GitHubからクローンする。
   ```bash
   git clone [対象のリポジトリ] push_swap
   ```
3. クローンしたディレクトリの中に入る。
   ```bash
   cd push_swap
   ```
4. コンパイルする。
   ```bash
   make        # ビルド（allと同じ）
   make all    # push_swapを生成する
   make clean  # オブジェクトファイルを削除する
   make fclean # オブジェクトファイルと実行ファイルを削除する
   make re     # fclean後に再ビルドする
   ```
5. 実行する（下記コマンドはbashで実行すること）。

- 普通に出力させる。
  ```bash
  ./push_swap 7 3 9 1 5 8 2 6 4 10
  ```
- ソートアルゴリズムを指定する場合（`--simple` / `--medium` / `--complex` / `--adaptive`）
  ```bash
  ./push_swap --complex 2 1 4 5 3
  ```
- benchmarkを出力させる場合（bench情報は標準エラー出力に出る）
  ```bash
  ./push_swap --complex --bench 2 1 4 5 3
  ```
- checker_linuxで動作が問題ないか確認する場合
  ```bash
  ./push_swap --bench $(cat test.txt) | ./checker_linux $(cat test.txt)
  ```
- shufを利用して性能確認をする場合
  ```bash
  shuf -i 0-9999 -n 500 > test.txt; ./push_swap --bench $(cat test.txt) 2> bench.txt | ./checker_linux $(cat test.txt)
  ```
- 同梱のテストスクリプトで一括確認する場合（エラー処理・各モードの動作をまとめて検証する）
  ```bash
  ./test.sh
  ```

### 生成AIの利用方法

本プロジェクトでは、以下の方針で生成AIを利用した。

#### 利用した場面
- **アルゴリズム調査** — チャンク分割ソートや基数ソート（LSD）など、push_swapで使われるアルゴリズムの仕組み・計算量・特徴の調査に利用した。
- **デバッグ** — メモリリークやエラー処理の不具合など、原因の切り分けや調査の補助として利用した。
- **テストコード作成** — 同梱のテストスクリプト（`test.sh`）の作成に利用した。テストスクリプトは提出物本体ではなく検証用の補助ツールであるため、AIによる作成を許容した。

#### 利用にあたってのルール
- 提出物である本体のCコードについては、AIを**説明・調査のみ**に使い、コードの生成・記述には使わない。実装は調べた内容を自分で理解した上で自力で書く。

#### 利用しなかった場面
- **コア実装** — スタック操作・パース・各ソートアルゴリズムなどの実装コードは、すべて自力で書いた。
- **Norm対応** — 42のコーディング規約（Norminette）への対応は自分で行った。
- **課題仕様の解釈** — 課題PDFの読解や要件の解釈（エラー処理の範囲など）は、AIに頼らず自分で判断した。

#### 学び・注意点
- **質問の仕方で回答の質が大きく変わる。** 漠然と聞くのではなく、前提条件や制約（使える操作が11種類に限られる、要素数の規模など）を具体的に伝えるほど、的確で有用な回答が得られた。

#### exit() vs return
* exit()はプログラム全体を即終了させる
* returnは今いる関数は抜けて、呼び出し元に戻る

#### exit()の仕様
* IBMから引用「プログラムを終了する前に、すべてのバッファーを削除し、すべてのオープン・ファイルをクローズします」とあり、実質的にリークは残らないが、明示的にfree()する。
